## 2. production 30k 채점 (n_windows 세 유동 통일)
| flow | R² (30k) | 이전 | 비고 |
|---|---|---|---|
| pipe | **0.9235** | = (이미 30k) | matched-Re11700 DNS |
| jet | **0.8876** | 0.906 (50k) | matched-Re7000 DNS(Nguyen-Oberlack); 30k가 50k보다 낮음 |
| wake | **0.6807** | **0.757 (2k!)** | Re3900 회전 wake; **30k가 2k보다 낮음** |

**핵심 발견:** 균일 30k가 **jet·wake 모두 악화**. 
- **wake: 데이터 15×↑가 오히려 R²↓ (0.757→0.681).** "undersampled" 가설 반증. 추정 원인 = 비정상 녹화(회전 12rpm, 후반 60s가 초반 4s와 다름 — drift/phase smearing). 초반(2k)이 가장 stationary.
- jet: 50k(더 많은 window-start)가 30k보다 좋음 — jet은 데이터가 많을수록 좋은 flow.
- → **n_windows는 균일 상수가 아니라 per-flow event-only stationarity로 선택**해야 함(DNS 아님; 데이터 양 = event 기준). per-flow 최적: jet 50k+ / wake 2k(stationary 창) / pipe 30k.

## 3. 실험 방향 — codex·opencode 토의 종합
**공유 병목(둘 다 일치):** midpoint deposit이 K-period path를 1 샘플로 collapse → within-path fluctuation이 residual → split-half noise subtraction이 그걸 noise로 제거. pipe는 within-path scatter가 진짜 noise라 생존, **wake는 진짜 난류라 붕괴**.

**우선순위 실험(config-only / one-path, 세 유동 동시):**
1. **all-points deposit + intra_energy_retention** — midpoint→path당 K점 deposit, within-path 분산을 retain(noise로 안 뺌). 코드 존재(retention이 0으로 zeroed된 게 이전 실패 원인). **가동 중**(env 토글 `EVENTFLOW_INTRA_RETENTION_*`, deposit `EVENTFLOW_CURVEFIT_DEPOSIT_MODE=path_balanced_all_points`).
2. **duration-aware noise weighting** — binary pipe-only path_noise_weighting을 연속 duration-gated로: 긴 path는 noise 빼고 짧은 path(난류 보존)는 덜 뺌.
3. **wake stationarity window** — event-only로 stationary 구간 검출해 wake n_windows 선택(이번 발견에서 도출).
