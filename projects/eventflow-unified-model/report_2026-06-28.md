# EventFlow — path-tracking 재탐색 + 환경 복구 (2026-06-28)

## 한 줄 요약
환경이 통째로 wiped된 상태에서 복구하고, 사용자 직관("velocities npz에서 per-event 위치를
얻을 수 있을 것")을 **fat velcache**로 실현해 path tracking을 raw-free로 만들었다. 그 위에서
path-tracking을 재탐색하던 중 **커밋된 wake cap14000이 비재현 false win**임을 밝혀 cap5200으로
되돌려 wake mean을 **0.6765→0.757(재현 가능)**로 회복. tracker-mode 거부 계열은 wake를 **악화**
(고섭동 난류 path를 버림)시킨다는 부정 결과도 확인 중.

## 1. 환경 복구
- 세션 사이 `~/.local` site-packages가 리셋됨(numpy/matplotlib만 남고 scipy/torch/numba/h5py
  소실). 추가로 **NAS raw 데이터셋 언마운트** + Metavision SDK 소실. 이것이 그간의 "process keeps
  exiting"의 실체였다.
- 대응: 의존성을 **프로젝트-로컬 `.pydeps/`**(gitignored)에 설치 → home 리셋에도 생존
  (`PYTHONPATH=.pydeps`). 사용자가 NAS remount → raw(wake 24GB/jet 21GB/pipe 8GB) + metavision
  (`/usr/lib/python3/dist-packages`) 복구 확인.

## 2. Fat velcache — raw-free path-tracking (commit 256104f)
- 진단: velcache는 `(vx,vy,w)` 속도만 저장하고, per-event **위치는 매 빌드 raw(metavision)로
  다시 읽고** 있었다(`data_loading.py`). 그래서 tracker_mode 하나만 바꿔도 24GB raw 재로드가 필요.
- 위치는 path-tracking 입력 지점에 이미 살아있다(사용자 지적). → `_save/_load_velocities_npz`가
  periods(per-event x,y,t,pol) + period_times도 같은 signature로 저장. fat HIT 시 raw/metavision을
  **건너뛰고** path tracking만 재실행. legacy thin cache는 raw 1회 읽고 자동 fat 업그레이드.
- 검증: 합성 e2e 2회(`HIT fat raw/metavision skipped`, samples bit-identical), wake 실데이터
  fat cache = **28.3M 이벤트 위치 캐시**. 이후 모든 tracker-mode 빌드가 `HIT fat`로 raw 없이 동작.
- 효과: fat cache는 NAS가 또 사라져도 남는 영구 재추적 자산. tracker 탐색을 대폭 가속.

## 3. wake cap14000 = false win → cap5200 복귀 (commit 2305542)
- 동일 코드로 in-session 재빌드: **cap14000 greedy mean R²=0.6765 < cap5200 greedy=0.7572**.
  cap5200 빌드는 기존 npz를 **bit-identical 재현**(paths=1258124, R²=0.7572 모두 일치) → version
  drift 아님, cap14000이 진짜로 더 나쁘다. 조밀 event가 근접장 triplet/연관 모호성을 키워 per-path
  추정을 노이즈화. 이전 "0.778"은 비재현(jet de-chop과 동일 패턴).
- → 재현 가능한 best cap5200으로 복귀, wake mean **0.757** 회복. README는 이미 5200을 명시해
  config↔README 일관성도 복원. profile + path-tracking GIF 갱신(`docs/assets/current`).
- 정직한 station별(cap5200, mean 0.757): 근접장 **x/D=1.06이 blocker**(uv=0.219, uu=0.570,
  U=0.659 — red가 U=1.3 shoulder를 못 잡음). x/D=1.54·2.02는 0.85~0.93로 양호.

## 4. tracker-mode 재탐색 (진행 중)
- `propagate_paths_aniso`에 잠자던 event-only 연관 gate 13종(precision/margin/mutual/reciprocal/
  graph 등)을 fat cache로 빠르게 sweep.
- **부정 결과(cap14000)**: precision_greedy(FB-require)=0.6097 < greedy=0.6765. **거부(rejection)가
  wake를 악화** — 고섭동 난류에선 velocity가 급변하므로 consistency/FB 거부가 **진짜 난류 excursion을
  버려** fluctuation을 과소평가. (이전 beam_consistent 실패와 일관.)
- cap5200(더 좋고 4.6× 빠름)에서 multi_candidate(permissive)·greedy_mutual·greedy_margin·
  precision_greedy·greedy_reciprocal를 재sweep 중. 가설: pipe(선형)는 거부가 도움될 수 있으나
  wake(고섭동)는 permissive greedy가 best일 가능성. (결과는 후속 보고)
